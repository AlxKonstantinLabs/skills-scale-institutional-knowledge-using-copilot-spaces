# OctoAcme Project Management Documentation

## Welcome to OctoAcme's Project Management Hub

This directory contains the OctoAcme project management framework—a lightweight, structured approach for planning, delivering, and improving projects with clarity, accountability, and continuous learning.

## About OctoAcme

OctoAcme projects follow a clear lifecycle designed to deliver customer value iteratively while maintaining strong ownership and alignment. The program emphasizes customer-first decision-making, data-informed execution, and psychological safety so teams can move quickly without sacrificing quality or stakeholder confidence.

## Key Principles

- Customer-first: prioritize customer value and usability.
- Iterative delivery: ship small, testable increments.
- Clear ownership: define named roles and responsibilities.
- Data-informed decisions: measure impact and adapt based on evidence.
- Psychological safety: encourage feedback, learning, and improvement.

## Process Summary

OctoAcme uses a five-stage lifecycle to manage work effectively. In the Initiation phase, teams validate the business need, identify stakeholders, define success criteria, and decide whether a project should move forward. Planning turns an approved initiative into a clear backlog with priorities, dependencies, scope estimates, and milestone planning.

During Execution, the team uses standups, project tracking boards, and a pull request workflow that emphasizes small, reviewable changes with issue links and acceptance criteria. Day-to-day delivery is coordinated by Project Managers, while Product Managers define outcomes and Developers and QA teams execute against defined quality expectations. Risk management and communication are embedded throughout the lifecycle via status updates, risk registers, and escalation paths as issues move beyond team-level resolution.

The Release phase standardizes deployment readiness by requiring acceptance criteria, passing CI and security checks, smoke tests, and a rollback or mitigation plan. After a sprint, release, or incident, OctoAcme uses Retrospectives and continuous improvement practices to capture learnings, assign action items, and measure progress over time.

## Getting Started for New Team Members

1. Read the [Project Management Overview](./octoacme-project-management-overview.md) to understand the program's principles, roles, and lifecycle.
2. Review the [OctoAcme Personas](./octoacme-roles-and-personas.md) to understand responsibilities for your role.
3. Use the relevant lifecycle document for the phase your project is in.
4. Apply the checklists and templates included in each document to keep project artifacts current and aligned.

## How to Use These Docs

- Each document includes a purpose statement and practical checklists.
- Use the templates and artifact guidance to keep the project repo organized and consistent.
- Keep project status, risks, release notes, and retrospective actions in the repository or project board as a single source of truth.
- Use the escalation paths in the docs when blockers or dependency issues require broader coordination.
